## Findings and corrections

1. **P1, introduced by PR: fresh first heartbeat loses protection at the provisional deadline.** In VpnBackgroundTaskManager.reconcile, the expired pending timer is processed before a newly read Running/TUN heartbeat. At 31 seconds, the manager stops an already acquired task even though the extension is now live. The subsequent poll may reacquire it, but the protection gap and notification teardown are unnecessary. Accept the fresh heartbeat before timing out. Regression failed before the correction, passed afterwards.
2. **P1, existing extension gap relevant to the new readiness behavior: failed config still creates a placeholder TUN.** createProbeTun falls through to the documentation-only configuration on a FAILED restore result. An unavailable/current-map rejection must leave the connection failed, without creating a VPN interface or an applied-config summary. Added early failure/invalid-payload exits. Regression failed before the correction, passed afterwards. This fallback predates PR #14; it is not attributed to the contributor.
3. **P1, existing async teardown race: create() completes after onDestroy.** onDestroy clears vpnConnection and requests destroy, but an outstanding create can subsequently establish an interface. The original post-await destroying check merely returns. Capture the connection through creation; if it is no longer current, destroy that captured connection before returning -1. Covers initial and replacement creates. Regression failed before the correction, passed afterwards. Actual SDK ordering still needs device verification.
4. **P1, existing rollback gap: failed native backend leaves the system VPN interface alive.** Releasing the Go duplicate alone does not destroy the HarmonyOS interface. Roll back the extension's native backend and system TUN after backend startup failure, bad probe, failed UI handoff, or startup exception. Regression for backend failure failed before correction and passed afterwards.
5. **P2, introduced timing expansion: 60 async queries are not a 15-second timeout.** Each native vpnConfig query has a 2-second context deadline. With 250ms sleeps, the loop can take approximately 135 seconds, exceeding provisional background protection. Add a 15-second wall-clock budget checked between queries. With the native deadline honored, an outstanding call can overrun the budget by up to roughly 2 seconds plus the retry sleep. It does not cancel a hung native promise. Added deterministic slow-query coverage.
6. **P2, introduced stale notification regression:** retaining protection indefinitely while telemetry is missing also republishes the last confirmed 'connected' title indefinitely. Preserve counters and task ownership, but publish 'VPN status unavailable' once no fresh Running/TUN evidence exists. This is particularly relevant to the abrupt process-loss case in #8. Added coverage. Retaining an acquired task under uncertain telemetry remains deliberate behavior requiring product/device validation; this correction does not infer tunnel liveness from task ownership.

## Issue #8 compatibility

Neither actual main nor PR #14 contains the automatic extension-restart patch described in the issue comments. refreshOrRecoverBackend still gates on backendStatus starting with STOPPED and only starts the UI backend. Therefore PR #14 does not resolve #8. A continuous task on the UIAbility does not establish extension liveness.

The proposed recovery path calling beginVpnConnection would also request provisional protection through this PR. Recovery must remain single-flight, respect persisted keep-connected intent, stop retries on explicit disconnect, and reset on a fresh extension heartbeat. Terminal timestamps can reject older status files after a new request, but two process instances writing concurrently are not isolated by a shared session identifier. Test old-session late terminal writes and auto-reconnect/manual-disconnect overlap on the actual combined patch before claiming compatibility. The issue's reported device result belongs to that contributor's separate build, not this branch.
